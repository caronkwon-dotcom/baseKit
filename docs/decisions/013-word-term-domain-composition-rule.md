# ADR 013. 단어·용어·도메인 조합 규칙

## 상태

Prototype 승인·구현

## 현재 구조와 문제

기존 `frontend/meta/terms.json`은 논리명, 물리명, 도메인의 결과만 보유해 물리명이 어떤 표준 단어와 약어로 만들어졌는지 검증할 수 없다. 개발자가 등록되지 않은 단어나 임의 약어로 컬럼을 만들면 BaseKit 명명 규칙을 일관되게 강제하기 어렵다.

## 결정

1. 단어는 용어를 구성하는 최소 단위이며 논리명, 영문명, 영문 약어를 가진다.
2. 단어는 일반 단어와 도메인 단어로 구분한다.
3. 용어는 한 개 이상의 등록된 단어를 순서대로 조합해 만든다.
4. 논리 용어명은 단어 논리명을 붙여 만들고, 물리 용어명은 단어 약어를 `_`로 연결한다.
5. 용어의 마지막 단어는 반드시 도메인 단어여야 한다.
6. 도메인은 마지막 도메인 단어와 데이터 타입, 길이, 소수점, 허용값을 연결한다.
7. 마지막 단어에 사용 가능한 도메인이 없으면 용어를 생성할 수 없다.
8. 등록되지 않은 단어와 약어는 표준 용어 생성에 사용할 수 없다.
9. 신규 단어는 논리명, 영문명, 약어의 동일·포함·문자열 유사도 검사를 거쳐야 저장할 수 있다.
10. 단어 상태는 신규등록, 수정·검토 중, 검수완료로 관리하며 검수완료 단어만 용어 조합과 도메인 연결에 사용한다.
11. 용어를 구성하는 단어 순서는 Drag & Drop으로 변경할 수 있으며 키보드·정밀 조정을 위해 좌우 이동 기능도 제공한다.

예시:

```text
사용자(USER, 일반) + 명(NAME, 도메인)
→ 논리 용어명: 사용자명
→ 물리 용어명: USER_NAME
→ 도메인: 명V100 / VARCHAR(100)
```

## 구현 경계

- `단어관리`와 `도메인관리`는 현재 JSON을 저장소로 사용하는 Prototype이다.
- `표준용어관리`의 조합 영역은 규칙과 UI 검증을 우선하며, 조합 용어를 `terms.json`에 최종 등록하는 승인 Workflow는 후속 작업이다.
- GitHub Pages에서는 브라우저에 임시 저장하고, 로컬 Vite 환경에서만 `frontend/meta/words.json`, `frontend/meta/domains.json`에 직접 저장한다.
- 기존 용어의 자동 분해와 공공표준 용어의 단어 후보 추출은 정제 작업으로 별도 수행한다.

## 공공표준 원본 반입 결과

- 행정안전부 공통표준단어 3,284건을 `frontend/meta/words.json`으로 반입한다.
- 유효 단어 3,229건은 원본반입 상태, 폐기·변경 55건은 폐기·변경 상태로 구분한다.
- 기존 BaseKit 단어와 논리명·약어가 동일한 항목만 기존 검수완료 상태를 유지한다.
- 공공표준용어 13,176건의 영문약어를 공식 단어 약어로 분리한 결과 12,523건은 완전분리, 653건은 미매칭이다.
- 미매칭 용어는 자동 생성하지 않고 단어 누락, 폐기단어 사용, 원본 예외를 검토한다.

## 후속 결정

- 동음이의어와 이음동의어 단어 정책
- 금칙어, 예약어와 약어 길이 규칙
- 복수 도메인이 같은 마지막 단어를 사용할 때 선택 기준
- 용어 승인·폐기·변경 이력과 영향 분석
- 논리 테이블 설계 및 DDL 생성 연결
