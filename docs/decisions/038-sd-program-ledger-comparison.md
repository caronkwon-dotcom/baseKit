# ADR 038: SD 프로그램 목록 분석의 기존 대장 비교 (group-programs-v0.3)

- 일자: 2026-11-04
- 상태: 사용자 방향 승인, ai-sd 구현·로컬 검증 완료, dev-pm 통합 전
- 작업 환경: sd / ai-sd. DB migration 없음. 공유 DB 적용 대상 없음.
- 관련: [ADR 037](037-sd-group-program-list.md), ADR 034, ADR 021

## 배경

STEP 03 프로그램 목록 분석(v0.2)은 그룹 요구사항만 보고 매번 신규 후보를 만들었다. 프로젝트의 기존 프로그램 대장(`BSDGPROG`)을 몰라서 요구사항 1건이 프로그램 1건으로 옮겨지고, 같은 프로그램이 분석마다 중복 등록될 수 있었다.

## 결정

1. **프로그램 도출 기준**: 프로그램은 실제 구현·배포·실행되는 단위다. 같은 화면에서 처리할 수 있는 목록·등록·수정·조회는 하나의 SCREEN 프로그램으로 통합하고, 독립 화면·배치·인터페이스·리포트는 분리한다. 요구사항과 프로그램은 N:M이다. SCREEN은 메뉴 1개와 1:1이라고 가정하지 않는다. 후보 상한은 기존 20건을 유지한다.
2. **대장 입력**: 같은 프로젝트의 `BSDGPROG` 전체를 `existingPrograms`로 LLM 입력에 포함한다(`ProgramLedgerReader`, 읽기 전용). 대장이 비어도 분석은 정상이며 모든 후보가 신규 기준이다. 전달한 대장의 크기와 누락 건수는 `existingProgramsInfo`로 요청 이력에 남긴다.
3. **판단**: LLM은 프로그램별 `decision`(REUSE/CHANGE/NEW), `existingProgramId`, `reason`, `changeSummary`를 반환한다.
4. **자동 보정 금지**: 존재하지 않는 기존 프로그램 ID, 타 프로젝트 ID, 입력으로 전달되지 않은 ID, 판단 누락·허용값 밖, ID 누락, NEW인데 ID 존재, 유효한 근거 요구사항 없음은 `reviewStatus=REVIEW_REQUIRED`와 원인 코드로 저장한다. 모델이 말한 값은 그대로 보존하며 NEW로 고치지 않는다. 검토 필요 후보는 등록할 수 없고 재분석 안내만 제공한다(자동 재시도 없음).
5. **등록 규칙**: 등록할 수 있는 것은 `decision=NEW`이고 검토 필요가 아닌 후보뿐이다. 유효한 REUSE/CHANGE는 기존 프로그램과 함께 표시만 하며, 신규 등록도 기존 프로그램 수정·요구사항 연결도 하지 않는다. 기존 프로그램 일부가 누락된 분석은 NEW 등록을 차단한다. 서버(`adopt`)가 같은 규칙을 강제한다.
6. **등록 직전 재확인**: NEW 채택 직전에 현재 대장을 다시 조회한다. 정규화한 이름이 같은 프로그램이 있으면 등록을 막고, 분석 이후 대장에 등록된 프로그램이 있으면 확인 표시가 있어야 등록한다. 의미상 유사성은 자동 확정하지 않고 이름이 비슷한 프로그램을 검토 대상으로 안내한다(`GET .../programs/adoption-check`).
7. **커버리지**: 입력 요구사항 전체가 "프로그램에 연결됨" 또는 "미분류"에 정확히 한 번 속하는지 서버가 단언한다. AI가 선언한 미분류와 서버가 보존한 미분류(AI 응답 누락)를 구분하고, 입력에 없는 ID와 중복 선언은 건수를 기록한다.
8. **과거 이력 호환**: v0.1/v0.2 결과는 변경하지 않고 계속 조회한다. 판단 정보가 없어 "대장 비교 미수행"으로 표시하며, 신규 등록은 기존처럼 가능하되 이름 중복과 분석 이후 등록 재확인은 동일하게 적용한다.
9. **입력·출력 한도**: 임의 기본값을 만들지 않는다. 속성 `standard-design.group-analysis.programs.max-input-chars`, `...max-output-tokens`는 기본 0(미설정)이며 이때 입력은 대장 전체를 보내고 출력 한도는 기존 동작(최소 4096)이다. 한도를 설정하면 대장을 FULL → COMPACT → MINIMAL로 줄이고, 그래도 넘으면 결정적 연관도 순서(요구사항 연결, 같은 그룹 출처, 용어 겹침)로 전달 대상을 고른다. 프로그램 수로 임의 절단하지 않으며 포함·누락 건수를 항상 기록한다. 요구사항 부분이 한도를 넘으면 실행하지 않는다. 한도는 사내 LLM 측정 후 확정한다.

## 영향

- 프롬프트 `group-programs-v0.3`, 요청에 `existingPrograms`·`existingProgramsInfo`, 응답에 판단·검토 필드와 `coverage`·`ledgerCompare`가 추가된다.
- 후보 API가 판단·검토·차단 사유·등록 가능 여부를 제공하고 `adopt`가 서버에서 차단한다.
- GROUP_DESIGN·GROUP_RECOMMENDATION과 기존 대장 수동 등록·수정은 변경하지 않는다.

## 제외

기존 프로그램 자동 수정, REUSE 요구사항 연결, 벡터 검색, DB migration, 프로그램 제외·삭제 API.
