# ADR 043: SD 프로젝트 관리 — 기존 목록·상세 워크스페이스 유지, 진입 흐름과 빈 공간 보완

- 일자: 2026-11-07
- 상태: PM 결정(방향 수정 반영), ai-sd 구현·로컬 검증 완료, dev-pm 통합 전
- 관련: [ADR 039](039-sd-project-master-postgresql.md)

## 경과
1. 처음 작업지시서(BK-SD-PROJECT-UI-001)는 공통 `MasterDetailMultiGrid`로 재구성하는 안이었고, 구현해 PR #61·#62로 병합했다. 그 결과 기존 워크스페이스의 **목록 폭 조절, 목록 접기, 목록 위 검색**이 사라졌다. 계획에는 적었지만 화면을 보기 전에는 영향이 전달되지 않았고, PM이 "화면 전환만 바꾸면 되는 것을 다른 화면으로 만들었다"고 바로잡았다.
2. 이 ADR은 그 결정을 되돌린 최종 상태를 기록한다. `MasterDetailMultiGrid` 버전(`ProjectManagementPage.tsx`)은 폐기했다.

## 결정
1. **기존 `ProjectListDetailWorkspace`(요구사항 관리·요구사항 그룹과 공유)와 `DataTable`을 그대로 쓴다.** 폭 조절, 목록 접기, 목록 위 검색(토글)을 유지한다. 공유 컴포넌트와 `styles.css`는 수정하지 않는다.
2. **진입 흐름만 바꾼다.** 첫 전체폭 목록 화면을 없애고 바로 목록+상세로 연다. 목록 조회가 끝나면 프로젝트 컨텍스트에 선택된 프로젝트 → 없거나 목록에 없으면 첫 행 → 0건이면 신규 편집 모드 순서로 선택한다(`projects/projectManagement.ts`). 목록이 로딩 중이거나 서버 오류면 선택·신규 모드 없이 안내만 표시한다. 자동 선택된 프로젝트는 프로젝트 컨텍스트가 된다. 삭제 후에는 그 자리의 다음 행(없으면 이전, 없으면 신규)을 연다. 검색 영역은 처음에 열려 있고 토글로 접을 수 있다.
3. **목록에 기간(시작일 ~ 종료일)을 표시**하고 고객명이 비어 있으면 `-`로 표시한다. 목록 기본 폭은 40%(드래그·키보드로 조절 가능).
4. **하단 빈 공간 보완**: 워크스페이스·래퍼는 끝까지 늘어나지만 `DataTable`은 행 수만큼만 높이를 가져 아래가 비어 보였다(실측: 1920×1080에서 멤버 래퍼 711px에 표 66px). 프로젝트 관리 화면의 표 래퍼에 행 구분선을 하단까지 이어 그려 빈 영역이 목록의 연장으로 보이게 했다(`.sd-project-mgmt-page` 범위의 CSS만, 다른 화면 영향 없음).
5. 기능은 그대로 보존한다: 등록·수정·삭제·복사, 낙관적 락, 미저장 확인, 멤버 추가·수정·삭제, 권한.

## 데이터 저장 위치(변경 없음)
프로젝트 본체는 서버 `BSDPROJ`. 프로젝트 멤버·멤버 마스터는 브라우저 localStorage(`basekit.standard-design.lifecycle.v1`)이며 서버 이전은 별도 단계(P3)다.

## 알려진 한계
- 1280px 폭에서 목록 40%일 때 멤버 표(8컬럼)가 가로 스크롤될 수 있다. 목록 폭을 줄이거나 목록을 접으면 해소된다.
- 근본 해결(DataTable이 영역을 채우는 구조)은 공통 컴포넌트 변경이 필요해 하지 않았다.
