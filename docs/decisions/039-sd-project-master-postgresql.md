# ADR 039: SD 프로젝트 마스터를 PostgreSQL로 이전 (P1)

- 일자: 2026-11-06
- 상태: 사용자 방향·P1 상세 PLAN 승인, ai-sd 구현·로컬 검증 완료, dev-pm 통합 전
- 작업 환경: sd / ai-sd. DB migration V26·V27은 PM이 백업 후 적용한다.
- 관련: ADR 017(테이블명), ADR 018(공통 컬럼), [ADR 031](031-standard-design-project-foundation-and-context.md)(프로젝트 기준 정보를 브라우저 저장소로 두었던 임시 구현)

## 배경

ADR 031은 프로젝트 기준 정보를 브라우저 localStorage에 두는 참조 구현이었고 "향후 관계형 모델로 전환"을 명시했다. 그 결과 브라우저마다 프로젝트 목록이 달랐다. 서버는 프로젝트 마스터를 가지지 않고 `BSDRREQ`의 `PROJECT_ID`만 알았으며, 프로젝트명은 클라이언트가 그룹 확정·AI 분석 요청에 실어 보내 스냅샷과 LLM 입력에 저장했다.

## 결정

1. **프로젝트 마스터는 PostgreSQL이 단일 원천이다.** 테이블 `BSDPROJ`(ADR 017 `B+SD+PROJ`, ADR 018 공통 컬럼 `REG_*`·`MOD_*`·`USE_YN`·`DEL_YN`, 낙관적 잠금 `VERSION`)를 V26에 `CREATE`만으로 만든다. 기존 테이블은 변경하지 않는다.
2. **기존 ID 백필(V27)**: 서버 테이블이 이미 참조하는 `PROJECT_ID`를 마스터에 등록한다(이름=ID, 고객·기간 비어 있음). 여러 번 실행해도 중복되지 않는다. 이름·고객은 이후 입력하거나 P2 이전 도구로 채운다.
3. **API** `/api/standard-design/projects`: 목록, 상세(하위 데이터 건수 `USAGE`), 등록, 수정(`VERSION` 필수, 충돌 409), 삭제. ID는 서버가 `SDP-<UUID>`로 생성한다. 필수값·기간 검증은 서버가 강제한다.
4. **삭제 정책**: 하위 데이터(요구사항·그룹·AI 그룹핑 분석·프로그램·프로젝트 메뉴)가 있으면 삭제를 막고(409, 건수 안내), 없을 때만 논리 삭제(`DEL_YN='Y'`)한다.
5. **프로젝트명은 서버가 정한다.** 그룹 확정·AI 분석의 스냅샷에는 마스터의 이름을 쓰고, 마스터에 없을 때만 요청 값, 그것도 없으면 `PROJECT_ID`를 쓴다(기존 동작과 호환). 저장된 스냅샷은 바꾸지 않는다.
6. **화면**: 프로젝트 관리와 프로젝트 선택 창은 서버 목록만 사용한다. 서버에 연결하지 못하면 오류와 "다시 조회"를 보여 주며 목업·브라우저 저장소로 대체하지 않는다. 브라우저에는 선택한 프로젝트 ID만 남긴다. 목록을 읽는 동안에는 저장된 선택을 유효로 간주해 진입 가드가 잘못 차단하지 않게 하고, 읽은 뒤 서버 목록으로 검증한다.
7. **기존 브라우저 저장소의 프로젝트·인력 정보는 읽지도 지우지도 않는다.** 이전 도구(P2) 전까지 보존한다. 프로젝트 인력(Member·투입)은 P3까지 기존 localStorage를 쓰며 프로젝트 ID만 서버 ID가 된다.
8. **서버의 프로젝트 존재 강제(FK)는 하지 않는다.** 기존 데이터 정리 후 별도 단계(P4)에서 한다.

## 배포 순서

백엔드(V26·V27 적용)를 먼저 배포한 뒤 프런트를 반영한다. 순서가 바뀌어 옛 서버가 ID만 돌려주면 화면은 ID 이름의 목록을 보여 주고, 저장·삭제는 서버 오류로 거부된다.

## 검증

H2 통합 테스트와 별도로, 환경변수(`BASEKIT_PG_PROJECT_REVIEW=true`와 DB 접속 정보)를 설정했을 때만 실행되는 PostgreSQL 전용 테스트(`ProjectPostgresTest`)를 둔다. 공유 DB가 아닌 임시 DB에서 실행해 V26·V27의 PostgreSQL 적용을 확인한다.

## 이번 범위에서 제외

브라우저 저장소 데이터의 서버 이전 도구(P2), 프로젝트 인력(P3), 서버 테이블의 프로젝트 FK(P4), WBS·DB 설계 스켈레톤(P5), 사용자 DB 연동.
