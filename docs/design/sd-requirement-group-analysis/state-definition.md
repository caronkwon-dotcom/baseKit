# 상태별 화면 정의

2026-10-07 · Prototype 예시와 SD 제품 계약을 구분한다.

## 독립 상태 축

그룹 상태(DRAFT/REVIEW_REQUIRED/CONFIRMED), 실행 상태(RUNNING/FAILED/REVIEW_REQUIRED/REVIEWED), 조회 상태(Loading/Error/Empty/Success), 과거 입력 여부를 별개로 표시한다. 그룹 REVIEW_REQUIRED는 재확정 필요이고 Analysis REVIEW_REQUIRED는 생성된 결과의 사람 검토 필요다. 상태 badge는 영역 제목과 함께 읽히도록 한다.

| 화면 상황 | 표시 | 허용 행동 | 보존 / 차단 |
|---|---|---|---|
| 그룹 미선택 | 그룹 선택 안내 | 목록 선택 | 실행/비교 없음 |
| DRAFT | 먼저 확정 안내 | 이력/과거 결과/기본정보 이동 | 새 실행 불가 |
| REVIEW_REQUIRED 그룹 | 변경 재검토·재확정 안내 | 과거 조회·검토·비교/기본정보 | 새 실행 불가, 이력 불변 |
| CONFIRMED 그룹 | 독립 분석 안내 | 입력 확인 후 실행 | 자동 실행 없음 |
| 미저장 초안 | 저장·확정 안내 | 기존 결과 조회, 기본정보 | 초안 유지, 실행 불가 |
| Snapshot 확인 | 읽기 전용 입력/Revision/총건수 | 취소/기본정보/실행 | 입력 편집·즉시 LLM 호출 없음 |
| 확인 중 입력 변경 | Modal 오류/기본정보 이동 | 닫기·최신 입력 재확인 | 실행 없음, 조용한 입력 교체 없음 |
| 실행 접수 실패 | Modal 내 오류 | 입력 유지·재시도/취소 | 신규 이력 없음(거절 확정일 때) |
| 실행 응답 유실 | 접수 확인 중/상태 조회 | 동일 요청 상태 확인 | 새 요청 차단; 서버 처리 여부 미정 |
| RUNNING | 실행 중/접수 시각/Snapshot | 상태 조회, 다른 이력·TAB 조회 | 결과 편집·검토완료 없음 |
| FAILED | 사용자용 실패 사유/Snapshot | 상태 재조회, Gate 허용 시 새 실행 재시도 | FAILED 원본 보존 |
| REVIEW_REQUIRED Analysis | 생성 결과 5영역 | 조회/비교/명시적 검토완료 | 그룹 확정·설계 반영 없음 |
| REVIEWED | 검토완료/검토 시각 | 조회/비교 | 원문 불변, 최종 채택 의미 없음 |
| 검토 표시 저장 실패 | Modal 오류 | 같은 표시 저장 재시도/취소 | 이전 상태 유지 |
| 현재 입력 이전 결과 | 과거 입력 배너 | 당시 Snapshot/결과 조회·검토·비교 | 상태를 STALE로 덮어쓰지 않음 |
| 이력 Empty | 아직 분석 없음 | CONFIRMED이면 새 실행 | 비교 불가, Error로 대체하지 않음 |
| 이력 Loading | 로딩 안내, 건수 확인 중 | 기존 선택 결과 참조 | 새 실행·비교 준비 차단 |
| 이력 Error | 조회 실패·다시 조회 | 조회 재시도, 기존 결과 | 기존 이력/선택 삭제 없음 |
| 선택 결과 Loading | 결과 로딩 영역 | 다른 이력 선택 | 확인 전 검토 표시 차단 |
| 선택 결과 Error | 결과 조회 실패·다시 조회 | 같은 ID 재조회 | 새 실행하지 않음, 원본 보존 |
| 결과 영역 Empty | 해당 영역 제안 없음 | 다른 결과 영역·Snapshot | 전체 이력 0건으로 표시하지 않음 |
| 완료인데 결과 누락 | 불완전 결과 안내 | 상태·결과 조회 | 검토완료/비교 가능하다고 가정하지 않음 |
| 비교 한쪽 Loading/Error | 해당 패널 안내·재조회 | 다른 패널 조회/비교 종료 | 대상 쌍과 다른 결과 유지 |
| 없는/권한 없는 Analysis | 조회 불가 안내 | 이력 재조회/다른 결과 | 시스템 오류·비밀정보 원문 노출 없음 |

## 전이

새 실행 접수 → 새 ID RUNNING → FAILED 또는 REVIEW_REQUIRED → 사용자 검토 표시 성공 → REVIEWED. 접수 거절은 새 ID가 없는 실패이고 실행 FAILED와 다르다. 조회 실패는 이 전이를 바꾸지 않는다. FAILED 재시도는 현재 확정 입력 확인 후 **새 ID**를 만들고 원 FAILED를 유지한다. RUNNING 중 새 실행 허용/중복 제한은 SD 정책 미결정이며 Prototype은 접수 완료 후 별도 독립 실행을 허용하는 제안이다.

Requirement/그룹 입력 변경은 과거 결과의 입력 비교 표시만 바꾼다. 그룹은 현행 업무 계약에 따라 재검토되며 Analysis 결과와 검토 표시는 보존한다. 검토 취소/삭제/이력 정리 행동은 V1에서 제공하지 않는다.

Loading/Error는 목록/상세/실행 접수/검토 저장/비교 각 범위에 국소 표시한다. 응답은 PROJECT_ID+GROUP_ID+ANALYSIS_ID+요청세대로 대조하고 늦은 다른 Context 응답은 UI에 적용하지 않는 계약이 필요하다. Prototype에는 실제 비동기 응답 경합을 구현하지 않았으므로 SD 제품 테스트에서 검증한다.
