# 실행·이력·검토·비교 흐름

2026-10-07 · 같은 프로젝트/그룹 Context를 유지한다.

## F01 기본 진입 / Context

그룹 관리 진입 → 목록 그룹 선택 → 우 Detail 기본정보 → 분석 TAB → 선택 그룹의 이력/결과. TAB 왕복은 선택과 초안을 보존한다. 다른 그룹 선택은 현행 미저장 보호를 거친 뒤 해당 그룹의 이력/마지막 결과를 조회한다. 이전 그룹의 완료 응답을 새 그룹 결과로 표시하지 않는다. 검색 범위 밖 선택은 상단 안내로 식별한다.

## F02 실행

CONFIRMED+저장 상태 → 새 분석 실행 → 입력 확인 Modal → 그룹 ID/이름/설명과 Requirement/Revision/설계 의견 검토 → 분석 실행 → 서버 최신성 검증 및 요청 접수 → 새 독립 ID RUNNING 행 → 상태 조회 → 생성 완료 REVIEW_REQUIRED → 결과 확인.

취소는 실행 이력을 만들지 않는다. 입력 수정은 Modal 닫기→기본정보에서만 수행한다. 확인 중 입력 변경은 실행 차단→최신 그룹 검토/확정→새 입력 확인이다. 접수 거절은 확인 화면을 유지한다. 응답 유실은 같은 요청 조회를 우선하며 새 요청을 만들지 않는다. 실제 실행/요청 멱등성은 SD 계약에 따른다.

## F03 이력 / 과거 결과

분석 이력 행 선택 → 해당 ID 결과 조회 → 결과 5영역과 입력 Snapshot 확인. 최신 결과 생성은 다른 결과를 자동 대체하지 않는다. 그룹 입력 변경 → 그룹 REVIEW_REQUIRED → 분석 TAB 실행 불가 → 기존 이력 선택 → 과거 입력 안내와 당시 Snapshot 조회 → 기본정보에서 변경 검토/재확정 → 새 Analysis 추가. 과거 결과는 그대로 남는다.

## F04 실패 재시도

FAILED 행 → 실패 사유/당시 Snapshot 확인 → 입력 확인 후 새 분석으로 재시도 → **현재 확정 그룹** Snapshot 확인 → 새 ID 생성. 실패한 ID는 수정하지 않는다. 그룹이 DRAFT/REVIEW_REQUIRED면 재시도 실행도 차단하고 기본정보 이동을 안내한다. 동일 당시 입력을 그대로 재실행하는 별도 행동은 V1 제안에 포함하지 않는다.

‘결과 다시 조회’/‘이력 다시 조회’/‘상태·결과 조회’는 읽기 재시도다. 실행이나 새 ID를 만들지 않는다.

## F05 결과 검토

완료 Analysis 선택 → 요약/업무구조/프로세스/Layout 추천/Program 후보 조회 → 필요 시 과거 입력 확인 또는 비교 → 검토완료 표시 → 의미 확인 Modal → 표시 저장 → REVIEWED. Modal 취소/저장 실패는 REVIEW_REQUIRED를 유지한다. 그룹 상태나 다른 Analysis 검토 상태는 바꾸지 않는다. 최종 설계 판단은 이후 별도 업무이며 후보 생성/전체 채택 버튼은 제공하지 않는다.

## F06 V1 비교

동일 그룹의 조회 가능한 완료 결과 2건 이상 → Analysis 비교 → 왼쪽/오른쪽 서로 다른 ID 선택 → 각 ID/시각/상태/입력 Snapshot 확인 → 입력 동일성 안내 → 공통 결과 영역 TAB 선택 → 각 제안과 근거 병렬 읽기 → 비교 닫기 → 직전 단일 결과 선택 유지.

RUNNING/FAILED/결과 없는 실행은 선택 목록에서 제외한다. 다른 그룹 결과를 섞지 않는다. 좁은 화면은 위/아래 배치하고 패널마다 ID를 반복 표시한다. 한쪽 Error 재조회가 다른 패널/대상 쌍을 바꾸면 안 된다. 자동 Diff, 병합, 채택이나 신규 설계 저장은 없다.

## F07 예외 / 복귀

이력 Empty는 새 실행 안내, Loading은 조회 중, Error는 다시 조회다. 결과 조회 실패는 같은 ID/선택을 유지한다. 그룹 선택/프로젝트 변경/MDI 이동은 기존 기본정보 초안 보호와 함께 동작한다. RUNNING 자체는 조회 전환을 막지 않으며 서버가 실행을 유지한다는 제안이다. 실행 접수 여부 불명일 때 같은 그룹의 새 요청은 조회로 해소할 때까지 차단한다. 프로젝트 재진입·새로고침 후 실행 상태 복구는 SD 서버 계약과 제품 검증 대상이다.

## Prototype 실행 방법

저장소 루트에서 정적 서버를 열어 `docs/design/sd-requirement-group/Prototype.html`을 조회한다. 분석 정상 예시는 좌측 ‘승인 검토’(GRP-002)→분석 TAB. DRAFT 예시는 ‘구매요청 처리’, Empty는 ‘발주 연계’에서 확인한다. 하단 검토 제어로 조회 Loading/Error, 실행 접수 실패/유실, 검토 저장 실패, 진행 완료/실패, 이력 0건을 모사한다. 기본정보 초안과 직접 추가/추천 근거 선택도 계속 검토할 수 있다. 새로고침은 모든 예시를 초기화한다. 하단 제어는 제품에 구현하지 않는다.
