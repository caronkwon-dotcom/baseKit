# 그룹 상태와 예외 UX 정의

2026-10-06 · 업무 상태와 화면 비동기 상태는 분리한다. 아래 코드명은 SD 계약 제안이며 확정 DTO가 아니다.

## 업무 상태

| 상태 | 편집 | 주요 Action | Gate / 지속 안내 |
|---|---|---|---|
| 작성중 (DRAFT 제안) | 기본정보·구성·사유 편집 | 두 추가 경로, 제거, 그룹 저장, 그룹 확정 | 확정 전 최신 설계 입력 불가 |
| 확정 (CONFIRMED 제안) | 읽기 전용 | 근거/상세 조회, 구성 수정 | 현재 검토 기준에서 다음 그룹 분석/설계 입력 사용 가능 |
| 재검토 필요 (REVIEW_REQUIRED 제안) | 구성 편집, 변경 검토 | 변경 확인, 영향 없음 판단, 그룹 저장, 그룹 다시 확정 | 기존 산출물 유지, 최신 Context Gate 재오픈 |

Requirement 업무 상태, Analysis 실행 상태, 그룹 상태는 서로 덮어쓰지 않는다. 상태는 색상과 텍스트로 표현한다. 확정된 그룹의 입력 사용 여부는 UI 배지뿐 아니라 실제 서버 검토 기준 확인이 필요하다.

## 전이

| Trigger | 전이 | 보존 / 조건 |
|---|---|---|
| 새 그룹 초안 | 없음 → 작성중 | 저장 전 영속 ID와 혼동하지 않음 |
| 직접/Analysis 항목 추가·제거·사유 수정 | 작성중 유지 / 재검토 필요 유지 | 초안 변경, 자동 저장·확정 없음 |
| 그룹 저장 성공 | 상태 유지 | 기본정보+구성 영속 저장 제안, 미저장 해제 |
| 사용자 확정 성공 | 작성중/재검토 필요 → 확정 | 저장 성공, 이름 유효, 포함 1건 이상, 모든 변경 검토, 현재 기준, 유효 참조 |
| 확정 그룹 구성 수정 승인 | 확정 → 작성중 | 이전 산출물 유지, 재확정 필요 |
| 포함 Requirement 수정/폐기 | 관련 그룹 → 재검토 필요 | 기존 구성 자동 변경/삭제 없음. 작성중 그룹 영향 표기 방식은 SD 합의 전 전체 그룹 재검토안 |
| 영향 없음 검토 / 변경 확인 | 재검토 필요 유지 | 확인 기준과 판단 저장, 이것만으로 자동 재확정 금지 |
| 또 다른 Requirement 변경 | 재검토 필요 유지 | 해당 항목의 검토 완료 해제, 새 변경 기준 표시 |
| 저장/확정 실패·충돌 | 기존 서버 업무 상태 유지 | 초안/입력/근거/선택 보존, 성공 배지 표시 금지 |

확정 활성 조건: 그룹 저장 완료, 그룹명 유효, 고유 Requirement 1건 이상, 포함 Requirement 프로젝트/접근/폐기 유효성, 변경 검토 0건 미완료, 동시성 검증 완료, 실행 권한, 저장·확정 진행 아님. 길이/상태 허용범위/권한은 SD 정책 확정이 필요하다. Prototype은 그룹명·포함 수·미저장·검토 기준·폐기 차단만 모사한다.

## Empty / Error / Loading / Unsaved

| 영역·상황 | 표현 / 다음 행동 | 보존 / 제한 |
|---|---|---|
| 프로젝트 없음 | 프로젝트를 먼저 선택하세요 / 기존 Context Selector | 업무 Action 비활성 |
| 전체 그룹 0건 | 아직 그룹이 없습니다 / 그룹 추가 | 상세 빈 영역 |
| 검색 그룹 0건 | 검색 결과가 없습니다 / 조건 변경 | 기존 선택 상세 유지, 검색 밖 선택 안내 |
| 포함 0건 | 두 추가 경로 안내 | 확정 비활성, Analysis 추가는 기존 실행이 있으면 가능 |
| Analysis 실행 0건 | 조회 결과 없음, 직접 추가 또는 별도 Analysis 화면에서 실행 | 그룹 내 분석 실행 없음 |
| 추천 0건 | 해당 실행 추천 없음 / 다른 Analysis 탐색 | 다른 실행 basket 유지 |
| 검색 후보 0건 | 검색 결과 없음 / 조건 변경 | 검색 밖 선택 유지 |
| 그룹/후보 조회 중 | 조회 중 + busy 메시지 / 기존 데이터는 이전 조회 표시 | 해당 데이터로 추가·확정 차단, 타 실행 basket 보존 |
| 조회 실패 | 실패 원인 범주 + 다시 조회 | 0건 성공으로 표시 금지, 이전 데이터와 초안 유지 |
| Analysis 상세 실패 | 실행 ID에 오류 표시, 상세 재시도 / 다른 실행 탐색 | 다른 실행 선택 유지, 실패 상세의 선택 차단 |
| 근거 삭제/접근 불가 | 근거 조회 불가, ID 및 사유 | 기존 구성 자동 삭제 없음, 사람의 판단과 기록 유지 |
| 저장/확정 중 | 처리 중, 중복 Action 차단 | Context 이탈 가드, 입력 보존 |
| 저장/확정 실패 | 해당 Action 실패 + 재시도 | 서버 성공 전 업무 상태·미저장 해제 금지 |
| 저장/확정 결과 불명 | 결과 확인 중 + 상태 조회 | 신규 요청으로 전체 재처리 금지, SD 계약 필요 |
| 동시 편집/409 | 다른 변경 존재, 최신 내용과 초안 비교 | 자동 덮어쓰기 없음, 원본 초안 보존 |
| 입력 오류 | 필드 인접 오류 + 오류 요약 + focus | aria-invalid/aria-describedby, 모달 뒤 메시지만 사용 금지 |
| 변경된 Requirement | 변경 검토 버튼, 검토 기준/현재 내용 | 신규 변경 재검증 전 확정 차단 |
| 폐기된 Requirement | 폐기됨 + 명시적 제거 | 자동 제거 없음, 확정 차단은 제안 |
| 그룹 미저장 | 버튼/요약의 미저장 표시, 계속 편집/저장 후 이동/버리고 이동 | 저장 실패 시 이동 금지 |
| 모달 선택 미반영 | 누적 선택 건수, 닫기 시 계속 편집/선택 버리기 | 최종 추가 전 그룹 미반영 |
| Requirement 신규 | 저장 후 포함 그룹 조회 가능 안내 | 가짜 ID/관계 조회 금지 |

Prototype은 추가 모달의 정상/Loading/Error/Empty, 저장/확정 실패·충돌 메시지, 미저장 이동 가드와 Requirement 변경/폐기 예시를 제공한다. 전체 그룹 0건·프로젝트 없음·개별 Analysis 실패·근거 삭제·권한·비동기 결과 불명은 문서 정의만 있으며 제품 구현 후 검증해야 한다. 모의 응답 제어는 제품에 포함하지 않는다.

비동기 Context 키는 프로젝트 ID / 그룹 ID / Analysis ID / 요청 세대 및 검토 기준을 포함하는 제안이다. 오래된 조회/확정 결과를 현재 Context에 적용하지 않는다. 변경 이벤트를 놓칠 수 있으므로 그룹 열기·저장·확정·후속 단계 입력 직전 최신 기준 확인이 필요하며 처리 방식은 SD 소유이다.
