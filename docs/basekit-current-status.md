# BaseKit 작업 기준 및 검수 기준 정리

## 1. BaseKit 현재 목적 정의

BaseKit은 SI 업무 시스템 개발 시 반복적으로 필요한 관리자 화면 구조를 미리 정의한 React 기반 표준 골격 프로젝트이다.

현재 단계의 목적은 완성형 업무 시스템을 만드는 것이 아니라, 향후 프로젝트마다 재사용할 수 있는 화면 구조, 메뉴 구조, 데이터 기준, 공통 관리 화면의 기본 패턴을 정리하는 것이다.

BaseKit은 다음 방향을 가진다.

* React 기반 관리자 화면 샘플 구축
* Header, Sidebar, Workspace, MDI Tab 구조 표준화
* 시스템관리 영역의 기본 화면 샘플 제공
* Mock 데이터 기반 화면 개발
* 향후 Spring REST API 연동 가능 구조로 확장
* SI 프로젝트 초기 개발 시 반복되는 화면 구성 비용 절감

현재는 React 화면 샘플 단계이며, DB/API 연동은 이후 단계에서 진행한다.

---

## 2. 현재 구현된 시스템관리 범위

현재까지 구현 또는 기준이 잡힌 시스템관리 범위는 다음과 같다.

### 현재 구현된 범위

* Admin Shell Layout
* Header 영역
* Sidebar 영역
* Workspace 영역
* MDI Tab 구조
* 사용자관리 Mock 화면
* 회사관리 화면
* 시스템 구조 정의

### 현재 기준이 필요한 범위

* 메뉴관리
* 공통코드관리
* 용어관리
* 역할/권한관리
* 조직관리

단, 오늘 작업에서는 전체 시스템관리 기능을 모두 구현하지 않는다.
현재 화면 구조를 유지하면서 Mock 데이터를 분리하고, 향후 확장 가능한 데이터 기준을 만드는 것을 우선한다.

---

## 3. 오늘 작업 목표

오늘 작업 목표는 기존 화면 구조를 유지하면서 시스템관리 Mock 데이터를 별도 데이터 파일로 분리하는 것이다.

### React 화면 샘플 단계 목표

* 사용자관리 화면의 하드코딩 Mock 데이터를 분리
* 메뉴 데이터를 별도 파일로 분리
* 필요 시 공통코드 샘플 데이터 추가
* 필요 시 용어집 샘플 데이터 추가
* 기존 UI 레이아웃 유지
* 기존 MDI Tab 동작 유지
* 신규 라이브러리 없이 현재 구조 안에서 정리

### 향후 Spring API 연동을 고려한 목표

* 화면 컴포넌트와 데이터 정의를 분리
* Mock 데이터 구조를 향후 API Response 구조로 전환 가능하게 설계
* 메뉴, 사용자, 공통코드, 용어 데이터의 기본 필드 기준 마련
* 컴포넌트 내부 하드코딩을 줄이고 데이터 기반 화면으로 전환

## 5. 시스템관리 샘플 메뉴 구조

시스템관리 샘플 메뉴는 다음 구조를 기준으로 한다.

```text
시스템관리
 ├─ 사용자관리
 ├─ 회사관리
 ├─ 메뉴관리
 ├─ 공통코드관리
 └─ 용어관리
```

### 오늘 화면 구현 기준

| 메뉴     | 오늘 기준                    |
| ------ | ------------------------ |
| 사용자관리  | 기존 화면 유지, Mock 데이터 분리    |
| 회사관리   | 기존 화면 유지, 필요 시 데이터 분리 후보 |
| 메뉴관리   | 메뉴 데이터 구조 기준 마련          |
| 공통코드관리 | 공통코드 샘플 데이터 기준 마련        |
| 용어관리   | 용어집 샘플 데이터 기준 마련         |

### 이후 확장 후보

```text
시스템관리
 ├─ 사용자관리
 ├─ 회사관리
 ├─ 조직관리
 ├─ 역할관리
 ├─ 권한관리
 ├─ 메뉴관리
 ├─ 공통코드관리
 └─ 용어관리
```

권한관리는 사용자, 역할, 메뉴, 조직, 회사 기준이 어느 정도 정리된 뒤 진행한다.

---

## 6. 공통코드로 관리할 항목과 별도 테이블로 관리할 항목 구분

`_CODE`로 끝나는 항목이라고 해서 모두 공통코드로 관리하지 않는다.

공통코드는 단순 선택값, 상태값, 여부값처럼 업무 구조에 종속되지 않는 값 위주로 관리한다.
반면 역할, 조직, 회사처럼 자체 속성과 관계를 가지는 항목은 별도 테이블로 관리한다.

### 공통코드 관리 후보

| 항목                   | 설명     |
| -------------------- | ------ |
| USE_YN               | 사용 여부  |
| DISPLAY_YN           | 표시 여부  |
| DELETE_YN            | 삭제 여부  |
| USER_STATUS_CODE     | 사용자 상태 |
| APPROVAL_STATUS_CODE | 승인 상태  |
| SYSTEM_TYPE_CODE     | 시스템 유형 |
| MENU_TYPE_CODE       | 메뉴 유형  |
| POPUP_YN             | 팝업 여부  |
| REQUIRED_YN          | 필수 여부  |

### 별도 테이블 관리 후보

| 항목            | 설명                |
| ------------- | ----------------- |
| USER_ID       | 사용자 자체 관리 대상      |
| COMPANY_CODE  | 회사/법인 정보 관리 대상    |
| ORG_CODE      | 조직 정보 관리 대상       |
| ROLE_CODE     | 역할/권한과 연결되는 관리 대상 |
| MENU_ID       | 메뉴 계층과 권한 연결 대상   |
| PROGRAM_ID    | 화면/프로그램 관리 대상     |
| AUTH_GROUP_ID | 권한 그룹 관리 대상       |

### 판단 기준

공통코드로 관리할 수 있는 경우:

* 값 목록이 단순하다.
* 별도 속성이 거의 없다.
* 다른 테이블과 복잡한 관계가 없다.
* 상태값, 여부값, 유형값에 가깝다.

별도 테이블로 관리해야 하는 경우:

* 자체 이름, 설명, 상태, 정렬, 권한 관계를 가진다.
* 다른 업무 데이터와 연결된다.
* 계층 구조가 있다.
* 이력 관리 또는 상세 관리가 필요하다.
* 사용자/회사/조직/권한처럼 시스템 운영 기준이 된다.

## 7. 고과장 작업 결과 검수 체크리스트

고과장 작업 완료 후 아래 기준으로 검수한다.

### 브랜치 확인

```powershell
git branch --show-current
git status
```

확인 기준:

* 현재 브랜치가 `feat/basekit-admin-data`인지 확인
* `dev-pm`에 직접 커밋하지 않았는지 확인
* 작업트리에 불필요한 변경 파일이 남아 있지 않은지 확인

---

### 변경 파일 확인

```powershell
git diff --name-status dev-pm..feat/basekit-admin-data
```

확인 기준:

* Mock 데이터 파일이 별도 위치로 분리되었는가
* 사용자 데이터가 컴포넌트 내부에서 빠졌는가
* 메뉴 데이터가 별도 파일로 분리되었는가
* 불필요한 CSS 변경이 없는가
* 신규 라이브러리 설치가 없는가
* 작업 범위를 넘어선 파일 변경이 없는가

---

### 화면 기능 확인

확인 항목:

* 기존 사용자관리 화면이 정상 표시되는가
* 회사관리 화면이 깨지지 않는가
* Sidebar 메뉴가 정상 표시되는가
* MDI Tab 동작이 유지되는가
* 기존 레이아웃이 바뀌지 않았는가
* 데이터 분리 후에도 화면 출력 결과가 동일한가

---

### 빌드 확인

```powershell
npm run build
```

확인 기준:

* 빌드가 성공하는가
* import 경로 오류가 없는가
* 사용하지 않는 변수나 모듈 오류가 없는가
* JSON 또는 JS 데이터 import 문제가 없는가

---

### 작업 범위 확인

아래 작업이 포함되었다면 범위 초과로 본다.

* 로그인 추가
* 권한관리 구현
* API 호출 추가
* Spring 연동 코드 추가
* 전체 라우팅 구조 변경
* 전체 CSS 재작성
* 신규 패키지 설치
* 대규모 리팩토링

오늘 작업은 Mock 데이터 분리와 데이터 기준 정리에 한정한다.

## 8. 오늘 작업 완료 후 다음 작업 우선순위

오늘 작업 완료 후 다음 작업은 아래 순서로 진행한다.

### 1순위. 메뉴 데이터화 정리

* 메뉴 데이터 구조 확정
* 1~3 Depth 메뉴 구조 지원
* Sidebar 메뉴 렌더링 기준 정리
* MDI Tab과 메뉴 데이터 연결 기준 정리

### 2순위. 사용자관리 화면 정리

* 사용자 Mock 데이터 구조 확정
* 검색 조건 정리
* 목록 컬럼 정리
* 상세/등록/수정 영역 분리 여부 검토

### 3순위. 회사관리 화면 정리

* 회사 데이터 구조 확정
* 법인/협력업체/내부회사 구분 기준 검토
* 사용자와 회사 관계 기준 정리

### 4순위. 공통코드관리 화면 샘플

* 코드그룹 목록
* 코드 목록
* 사용 여부
* 정렬 순서
* 코드 그룹/코드 상세 구조 정리

### 5순위. 메뉴관리 화면 샘플

* 메뉴 ID
* 상위 메뉴 ID
* 메뉴명
* 메뉴 레벨
* 정렬 순서
* 경로
* 사용 여부

### 6순위. 용어관리 화면 샘플

* 표준 용어
* 도메인
* 데이터 타입
* 설명
* 예시
* DB 컬럼명 기준 정리

### 7순위. Grid 공통 컴포넌트 검토

* 현재 화면 패턴을 기준으로 공통 Grid 필요성 검토
* 라이브러리 도입 전 Adapter 방식 검토
* 컬럼 정의와 데이터 소스 분리 기준 검토

### 8순위. 권한관리 설계

* 사용자
* 역할
* 메뉴
* 회사
* 조직
* 권한 그룹

위 기준이 정리된 뒤 권한관리를 설계한다.

### 9순위. Spring API 연동 구조 검토

* Mock 데이터 구조와 API Response 구조 비교
* API Adapter 계층 검토
* React 화면이 API 변경에 직접 흔들리지 않도록 구조 설계
* 사용자관리, 메뉴관리, 공통코드관리 순서로 API 연동 검토

오늘 작업은 다음 조건을 만족하면 완료로 본다.
